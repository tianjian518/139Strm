# 139Strm

移动云盘（139 / 和彩云）专用的 STRM 生成器 + 302 直链服务，**原生支持 `.cas` 秒传文件播放**。

**为什么会有这个项目**：SmartStrm 是闭源项目，官方驱动列表里没有移动云盘，只能通过 OpenList 转接。
如果你的 OpenList 部署在境外（比如 Hugging Face Spaces），播放时所有流量都要绕一圈境外中转，卡到没法看。

本工具直连移动云盘官方接口，不经过任何中转：

```
Emby 播放器 ──► 139Strm (/d/xxx) ──302──► 移动云盘 CDN
                     │
                只做一次跳转
               不中转视频流
```

## 核心能力：`.cas` 秒传文件也能播放

移动云盘里的 `.cas` 文件通常只有几百字节——它是真实文件的"特征码"，不是视频本身。
播放器打开它只会拿到一段 JSON，根本放不了。

139Strm 会在**播放的那一刻**把它还原成真文件：

```
播放器请求 /d/xxx?cas=电影.mkv.cas
    │
    ├─ 1. 下载 264 字节的 .cas，解出 SHA256 / 大小 / 原始文件名
    ├─ 2. 调 /file/create 做秒传 → 云端"凭空"还原出一个 4.24GB 的真文件（约 0.7 秒）
    ├─ 3. 取这个临时文件的真实直链，302 给播放器
    └─ 4. 停止播放（或直链到期）后自动彻底删除临时文件，云盘里不留痕迹
```

**不占你的云盘空间**（秒传是引用，不是复制），**不消耗上传流量**，
**一部片子一次播放只秒传一次**——播放过程中换直链、拖进度条、并发探测
都复用同一个临时文件，只重新取一条直链，不会反复秒传出新副本。

## 快速开始

> ### ⚠️ 先读这一条：数据会不会丢，全看"挂载"
>
> 139Strm 有三样数据，都必须落到**你 NAS 上的真实文件夹**，不能留在容器里：
>
> | 数据 | 容器里的路径 | 挂到 NAS 的哪里（举例） |
> | --- | --- | --- |
> | 配置 + 云盘凭据 | `/app/config` | `/docker/139strm/config` |
> | 任务列表（和配置文件同目录，自动跟着） | `/app/config/tasks.json` | 同上 |
> | 生成的 STRM | `/strm` | `/docker/139strm/strm` |
>
> **不挂载 = 数据只写在容器内部，容器一删除重建（升级版本就是重建）就全部清空。**
> 挂载之后，无论重启、重建还是升级版本，配置和 STRM 都还在。
>
> 拿不准自己挂没挂：打开 139Strm → **系统设置** → 最上面「💾 数据存储」，
> 会直接显示每个目录是「✅ 已挂载」还是「❌ 未挂载」。

### 方式一：Docker（推荐，支持 AMD64 / ARM64）

```bash
mkdir -p 139strm/{config,strm} && cd 139strm

cat > docker-compose.yml <<'EOF'
services:
  139strm:
    image: tianjian518/139strm:2.1.6
    container_name: 139strm
    restart: unless-stopped
    ports:
      - "8025:8025"
    volumes:
      - ./config:/app/config
      - ./strm:/strm
EOF

docker compose up -d
```

访问 `http://你的IP:8025`

### 方式二：直接运行

```bash
pip install -r requirements.txt
python app.py          # 默认端口 8025
```

### 方式三：自己构建

```bash
docker build -t 139strm .
docker run -d --name 139strm --restart unless-stopped \
  -p 8025:8025 \
  -v ./config:/app/config \
  -v ./strm:/strm \
  139strm
```

### 数据存储与挂载（飞牛 OS / 群晖 等图形界面）

在飞牛里建容器，最关键的是填「存储空间」那一步：

| 容器内路径 | NAS 上的文件夹 | 装的是什么 |
| --- | --- | --- |
| `/app/config` | `/docker/139strm/config` | 配置 + 云盘凭据 + 任务列表 |
| `/strm` | `/docker/139strm/strm` | 生成的 STRM（Emby / 飞牛影视也挂这个） |

步骤：

1. 先在 NAS 上把这两个文件夹建好（文件管理里新建 `docker/139strm/config` 和 `docker/139strm/strm`）
2. 新建（或编辑）容器 → 找到「存储空间」/「卷 Volume」那一项
3. 点「添加」：左边选 NAS 文件夹 `docker/139strm/config`，右边容器路径填 `/app/config`
4. 再加一条：`docker/139strm/strm` → `/strm`
5. 端口映射填 `8025:8025`
6. 启动后，进「系统设置 → 💾 数据存储」确认两项都显示「✅ 已挂载」

> **已经丢过一次怎么补救**：如果旧容器**还没删**（只是停止状态），
> 可以在飞牛的终端里执行 `docker cp 旧容器名:/app/config ./config` 把配置和任务拷回来；
> 容器一旦被删除，里面的数据就真的找不回来了。

> **关键点**：`./strm` 这个目录必须同时挂载给 Emby / Jellyfin，两边路径保持一致。

### 部署模式选择

- `docker-compose.yml`（**默认 / 飞牛等套件环境**）：端口映射模式 `8025:8025`，最稳。
- `docker-compose.host.yml`（**Linux 服务器 / 与 Emby 同主机**）：host 网络模式，便于 Emby 容器内直连 8025。

二选一拷贝成 `docker-compose.yml` 即可使用。

## 三步上手

### 第 1 步：配置移动云盘（左侧「存储管理」）

1. 浏览器开**无痕窗口**，登录 <https://yun.139.com/>
2. 按 `F12` 打开开发者工具 → 切到 **网络（Network）**
3. 在网页里随便点开一个文件夹，触发一个请求
4. 点开任一请求 → 右侧 **请求标头（Request Headers）** → 找到 `Authorization`
5. 它的值形如 `Basic xxxxxxxx...` —— **复制时把开头的 `Basic ` 和空格去掉**，只留后面那串 Base64

> ⚠️ 官方实现里有硬性校验，带了 `Basic` 前缀会直接报
> `authorization should not include Basic prefix`。

**免抓包替代方案**：登录 <https://mail.10086.cn/> 后复制完整 Cookie（需含 `Os_SSo_Sid` 和 `RMKEY`），配合手机号可免密登录。

填到界面后点 **保存配置** + **测试连接**。看到账号 + 根目录条目数 + 凭据有效期即表示成功。

### 第 2 步：填好「基础地址」

**基础地址**是写入每个 strm 文件里的前缀，播放器播放时会请求这个地址。它必须是**播放器能访问到的地址**。

> **在飞牛 OS 的 Docker 中部署时（最常见场景）**：139Strm 是飞牛 Docker 里的一个容器，飞牛影视是飞牛系统自带应用。
> 容器默认会分到 docker 内部 IP（如 `172.17.0.5`），**这个地址不能填**——它每次重启都可能变，且飞牛影视不一定能稳定访问。
> 正确做法：给 139Strm 做端口映射 `8025:8025`，然后把**基础地址**填成下面任一种：
> - `http://127.0.0.1:8025`（飞牛系统回环，最稳，推荐）
> - `http://<飞牛宿主机的私有 IP>:8025`（在飞牛「设置 → 网络」里看到的那个 IP）
> - 注意：**不要填公网 IP、不要填 `172.17.0.x` 容器 IP、不要加 `https`**（本项目只跑 http）。
> 改完基础地址后，必须用**强同步**重新生成 strm，否则旧文件里还是旧地址。

### 第 3 步：建任务（左侧「任务管理」）

- 点右上 **+ 添加任务**
- 任务名：`movie`（输出会落在 `/strm/movie/…` 下，**任务名就是壳目录**）
- 扫描路径：填云盘里的目录（如 `/video/movie`），或点「📂 浏览」进到对应目录再点「+ 在此目录新建任务」
- 同步模式：**增量**（已有跳过） / **强同步**（覆盖重生成）
- 同步删除：勾上后，云盘里删了的电影，本地 strm 也会自动跟着删（类似 `rsync --delete`）
- 定时（crontab）：留空 = 只手动点「运行」；想自动跑就填：
  - `0 3 * * *` 每天凌晨 3 点
  - `*/30 * * * *` 每 30 分钟
  - `0 */6 * * *` 每 6 小时整点
- 任务建好后，点表格里的 ▶ 立即跑一次，或点页面右上 **▶ 运行所有** 一次跑完全部启用任务

> 任务运行中，状态条会出现红色 **⛔ 强制终止** 按钮：点它会立即中断当前任务并跳过队列后续任务，已生成的 strm 会**保留**。下次以「增量」再跑会从断点继续，不会重复生成。

---

## 同步模式与同步删除（每任务独立）

| 字段 | 说明 | 默认 |
|---|---|---|
| `sync_mode` | `incremental` = 增量（同名 strm 已存在就跳过，只补新的）；`force` = 强同步（全部重新生成、覆盖旧文件） | `incremental` |
| `delete_orphans` | 删除孤儿：本次扫描结束后，清理**本次同步范围内、源头已不存在**的 `.strm`（不会动其他任务/手动放的 strm；只删 .strm，不删字幕/图片） | 强同步默认开；增量默认关 |

**删除孤儿** = 类似 `rsync --delete` 的镜像式同步：云盘里把电影删了，本地 `.strm` 也会跟着删。

任务里还有三个**可选覆盖**字段，留空就用「系统设置」里的全局默认：媒体文件后缀、复制到本地的后缀、文件大小阈值。

## 接入 Emby / Jellyfin

1. 把 `./strm` 目录挂载给 Emby 容器（例如同样是 `/strm`）
2. Emby 后台 → 添加媒体库 → 类型选"电影"或"电视剧" → 路径选 `/strm`
3. 扫描即可入库（因为 strm 只有几十字节，入库非常快）
4. 播放时 Emby 请求 strm 里的地址，本项目 302 跳到移动云盘直链

### 生成的文件长什么样

| 云盘里的文件 | 生成的本地文件 | strm 内容 |
|---|---|---|
| `VID_20220807.mp4` | `VID_20220807.mp4.strm` | `http://192.168.1.10:8025/d/Fk9se2Ip...` |
| `电影.mp4.cas` | `电影.mp4.strm` | 同上 + `?cas=%E7%94%B5%E5%BD%B1.mp4.cas`（自动去掉 `.cas` 尾巴） |

`?cas=` 这个参数是关键——它告诉服务端"这个文件需要秒传还原"，普通文件不带这个参数。

## 已知限制

### 1. 临时文件会短暂占用文件列表

播放 `.cas` 时，云盘根目录的 `139STRM_TEMP` 文件夹里会短暂出现一个还原出来的文件。
这是秒传还原的必要代价——OpenList 的 CAS 实现也是同样的做法。

同一部片子在临时目录里**始终只保留一份**：播放中换直链只复用，不会新增；
重新秒传前会先清掉这部片子之前的副本（含上次异常退出留下的残骸）；
停止播放后按 `cas_temp_ttl` 到点自动彻底删除。目录本身只有一个，且被程序记住 ID，不会重复创建。

### 2. 秒传还原依赖云端源数据还存在

如果原始文件在移动云盘服务器上已被彻底清理，秒传会失败并提示
`秒传失败：云端已不存在该文件的源数据，.cas 已失效无法还原`。这种情况下没有任何办法恢复。

### 3. 直链有有效期

移动云盘直链带时效签名（实测约 15 分钟）。本项目按直链自身的过期时间缓存（留 60 秒余量，
最多缓存 15 分钟），过期会重新获取。Emby 每次播放都会重新请求，不受影响。

### 4. 凭据有效期

Authorization 约 1~2 个月过期，过期后重新抓包即可。程序会在剩余不足 15 天时尝试自动刷新，
刷新失败会提示重新获取。

### 5. 只有新版个人云支持 CAS 播放

`cloud_type` 必须是 `personal_new`。家庭云 / 群组云 / 旧版个人云走的是另一套接口，未实现秒传还原。

### 6. 超大 CAS 可能因账号「权益」不足而还原失败

秒传还原走的是移动云盘的 `/file/create`「极速上传」接口，部分账号的会员权益对**单文件大小**有上限。
实测：约 **5 GB 以内**的 CAS 可正常还原播放（2~5.3 GB 均验证通过），**6 GB 以上**会报
`权益不足`，返回 502。

这是**移动云盘账号等级限制，不是 139Strm 的问题**，代码层面无法绕过：
- 升级移动云盘会员（开通更高「权益」）后通常即可还原更大的文件；
- 或只把较小的 CAS 文件用于本项目的秒传播放。

报错时日志与 `/api/link` 接口会明确提示：`账号秒传权益不足，无法还原大小约 X GB 的文件`。

## 和 SmartStrm 的关系

| | SmartStrm | 139Strm |
|---|---|---|
| 源码 | 闭源，不可修改 | 开源可读可改 |
| 移动云盘 | 不支持，需 OpenList 转接 | **原生直连** |
| `.cas` 秒传播放 | 需配合 OpenList-CAS | **原生内置** |
| 支持网盘 | 夸克/115/123/天翼/光鸭等 | 仅移动云盘 |
| 302 直链 | Pro 付费功能 | **免费内置** |
| 定时任务 | 支持 | **支持（每个任务独立 crontab，增量 / 强同步 / 删除孤儿）** |
| 运行中终止 | 支持 | **支持（红色 ⛔ 按钮一键中断）** |
| 部署位置 | 需与网盘网络通畅 | 任意位置，只要播放器能访问 |

如果你只需要移动云盘，本项目更轻、更快、不依赖境外中转。
如果你需要管理多个网盘，SmartStrm + 境内 OpenList 转接仍是更好的选择。
